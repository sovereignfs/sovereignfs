# sovereign-infra — deployment/hosting kit

A GitHub-template repo (not a library or service) providing operators with
a self-hosting deployment kit for [sovereign](sovereign.md) on a plain
Ubuntu 24.04 VPS. Operators fork/use it as a template, run `configure.sh`
locally to set domains, bootstrap the VPS with `bootstrap/setup.sh`, then
push git tags to trigger GitHub Actions CI/CD that installs secrets,
configures the Caddy reverse proxy, and deploys the published Sovereign
Docker images. Deliberately avoids Terraform/Ansible/managed-cloud
dependencies in favor of a minimal script + GitHub Actions approach.

See [two-repo-deploy-model](../concepts/two-repo-deploy-model.md) for how
this pairs with `sovereign`'s own release process.

## What it manages/deploys

- **Caddy** reverse proxy (auto-TLS via `caddy/Caddyfile` importing
  `caddy/conf.d/*.caddy`, run via its own `docker-compose.yml`)
- **Docker Compose–based app deployment** — fetches `sovereign`'s
  docker-compose files and images from GHCR at deploy time rather than
  owning them
- **age-encrypted `.env` secrets** (encrypt/decrypt scripts,
  `env.example.yml` → `env.yml` → `generate-env.js` pipeline)
- **VPS bootstrap/hardening** (`bootstrap/setup.sh`, run as root)
- **Daily/tag-triggered encrypted backups** pushed to a separate backup
  git repo (`scripts/backup-sovereign.sh`, `restore-sovereign.sh`,
  `install-backup-cron.sh`)

All orchestration runs through `.github/workflows/sync.yml` (any tag →
sync secrets/Caddy; a `v*` tag → also deploy).

## Top-level structure

- `apps/` — per-app deployment config; `apps/sovereign/` holds
  `.env.example` and a compose override (no `compose.yml` — fetched from
  the sovereign release at deploy time); `apps/_template/` is a
  copy-me skeleton for adding new non-sovereign apps; `apps/_plugin-tokens/`
  holds tokens for building private Sovereign plugins
- `bootstrap/` — `setup.sh`, one-time VPS provisioning/hardening, run as
  root
- `caddy/` — `Caddyfile`, `conf.d/sovereign.caddy` (generated by
  `configure.sh`), `conf.d/_template.caddy.example`, its own
  `docker-compose.yml`
- `scripts/` — env generation/encryption/decryption, backup/restore, cron
  installer, `logs.sh` docker-logs wrapper
- `docs/` — `ports.md` (port registry) and
  `sovereign-deploy-workflow.md` (the two-repo deploy model)
- `configure.sh`, `env.example.yml` — top-level one-time domain/env setup
- `.github/workflows/` — CI/CD (`sync.yml`)

## Relationship to sovereign

This is explicitly the **"Operator"** half of a documented two-repo model,
paired with [sovereign](sovereign.md) (the **"Provider"**, which owns app
code and publishes Docker images to GHCR on `v*` tags). `sovereign-infra`
contains no application code — it deploys and operates published
`sovereign` images: pushing a matching `v*` tag here verifies the GHCR
image exists and deploys it to the VPS. Purely deployment/hosting
infrastructure, decoupled from the platform's own release process.
